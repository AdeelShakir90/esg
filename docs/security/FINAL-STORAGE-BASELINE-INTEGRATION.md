## SQL privileges are not RLS authorization

The proposed snapshot has anon/authenticated SQL SELECT/INSERT/UPDATE/DELETE on Storage and corresponding table-derived column rights. Those prerequisites alone do not allow a caller to access rows protected by RLS. The canonical static SELECT comparisons must verify owner/reviewer restrictions, tenant/document metadata matching and the canonical CASE guard. They do not establish safety of existing Storage write policies or enable application writes. Live synthetic role-based tests are still required. Service-role access and existing signed URLs are outside ordinary user RLS checks.
